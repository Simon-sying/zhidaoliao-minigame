# 云开发（CloudBase）与广告：开通、配置、成本与发布清单

本项目的成本原则：**能力一次写好，但延迟启用**。代码里云端排行榜/防作弊和激励视频都已实现，默认开关关闭，开发与冷启动期零固定成本；临近上线再一键开启，先吃免费额度。

> 以下价格与门槛为整理时（2026-09）的公开口径，实际以微信/腾讯云控制台当天展示为准。
> - 云开发定价与免费额度：<https://tcb.cloud.tencent.com/pricing> 、<https://cloud.tencent.com/document/product/876/75213>
> - 小游戏流量主门槛（累计独立访客 UV > 500）：<https://developers.weixin.qq.com/minigame/dev/guide/open-ability/ad/ad>
> - 小游戏包体限制（主包 ≤ 4MB，总分包 ≤ 30MB）：<https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-package.html>

## 一、为什么仍要用云开发（而不是完全不要）

每日挑战的排行榜是本游戏的核心留存与传播点。如果成绩只存本地：

- 玩家可随意改本地数据，排行榜失去公信力；
- 无法做跨用户的“今日同一套题、看谁排第几”。

所以**排行榜与成绩必须云端权威**。但开发期和上线初期用户极少，没必要为此常驻付费服务：

- 纯文本题库仅几百 KB，**直接打进包内**，不做远程题库/CMS（省掉数据库读、CDN 与一套管理后台）；
- 云函数按调用计费、有免费额度，冷启动期几乎不产生费用；
- 客户端所有云端调用都包了降级，云没开/没网时休闲玩法照常，榜单显示“本地预览虚拟数据”，且不伪造任何名次。

### 成本测算（保守）

| 阶段 | 方案 | 预估月固定成本 |
| --- | --- | --- |
| 开发 / 内测 | `USE_CLOUD=false`，不部署 | **0 元** |
| 上线初期 | 云开发免费环境（约 3000 资源点/月，额度到期可续期） | **0 元**（额度内） |
| 用户增长、免费额度吃紧 | 升级个人版等付费档（约 **19.9 元/月** 起，以控制台为准） | 约 19.9 元/月起 |

每日挑战每个“提交成绩 + 拉榜单”是少量云函数调用与数据库读写；只对**真正玩挑战的日活**产生，量级在免费额度内能覆盖相当规模。题库不下发数据库、不做实时能力，避免最花钱的两块。

## 二、开启云开发（约 10 分钟）

### 1）创建环境并拿到环境 ID

1. 用已填真实 AppID 的工程打开微信开发者工具，顶部进入「**云开发**」控制台（首次需开通）。
2. 新建环境，套餐选择**免费/基础额度**档；地域按用户就近（一般选国内）。
3. 创建完成后复制**环境 ID**（形如 `zhidaoliao-9gxxxxxxx`）。

### 2）填配置

打开 `src/config/index.js`：

```js
CLOUD: {
  USE_CLOUD: true,                 // false → true
  ENV_ID: 'zhidaoliao-9gxxxxxxx',  // 填入你的环境 ID
  SHOW_PREVIEW_BOARD_WHEN_LOCAL: true
}
```

### 3）创建数据库集合与权限

在云开发控制台「数据库」新建两个集合：

- `users`
- `challenge_scores`

**权限**：把两个集合的读写权限都设为“**所有用户不可读写 / 仅管理端（云函数）可访问**”（自定义安全规则里读写都为 `false` 也可）。这样客户端无法直接改库，只能通过云函数——这是防作弊的前提。

**索引**（数据量变大后用于加速榜单与排名统计）：

- `challenge_scores`：对 `challengeId` 建普通（非唯一）索引；
- 可选复合索引：`challengeId` 升序 + `score` 降序。

### 4）部署 3 个云函数

在开发者工具左侧 `cloudfunctions/` 目录（已在 `project.config.json` 指定 `cloudfunctionRoot`）：

- 分别右键 `login`、`submitScore`、`getLeaderboard` →「**上传并部署：云端安装依赖（不上传 node_modules）**」；
- 确认每个函数在线测试可返回：
  - `login`：`{ ok:true, openid:'...' }`；
  - `getLeaderboard`（传入当天 `challengeId`，形如 `20260920`）：`{ ok:true, list:[...], myRank:null }`；
  - `submitScore`：先用真机打完一局，在结果页应出现“提交成功，今日榜第 N 名”。

> `submitScore` 目录内已包含 `bank.json`（题库副本）。**每次扩题后必须重跑 `npm run export-bank` 并重新部署 `submitScore`**，否则云端仍按旧题库复核。

### 5）验证降级

- 无网络或云函数异常时：结果页应提示未进入排行榜（不发奖、不伪造名次），休闲刷题、错题、收藏、掌握度均不受影响。

## 三、配置激励视频广告（UV > 500 之后）

1. 小游戏累计独立访客 **UV 超过 500** 后，在公众平台「流量主」中开通并新建一个「**激励视频广告**」广告位，得到广告位 ID（形如 `adunit-xxxxxxxxxxxxxxxx`）。
2. 打开 `src/config/index.js`：

```js
ADS: {
  ENABLED: true,
  REWARDED_VIDEO_UNIT_ID: 'adunit-xxxxxxxxxxxxxxxx',
  CASUAL_OFFER_INTERVAL: 12,   // 休闲模式每答约 12 题最多主动提供一次“知识总结”
  MIN_INTERVAL_MS: 30000       // 单局广告最短间隔，避免打扰/被限流
}
```

3. 重新提审/发版即可。本项目三个广告位都由用户**主动点击**触发，符合激励广告的体验与合规要求：
   - `retry`：每日挑战失败后「看视频·再挑战一次」；
   - `summary`：休闲刷题中主动领取「今日知识总结」；
   - `hint`：答题前主动「看视频要提示」。
4. 真实广告只有在回调 `res.isEnded === true`（完整看完）时才发奖励；加载失败/onError 自动降级为模拟广告，保证流程不崩。

## 四、隐私与合规（上线必备，建议尽早办）

- 在小游戏后台填写并发布「**用户隐私保护指引**」，涉及本地存储、设备信息、广告等用途需如实勾选；必要时在小程序内接入隐私授权弹窗（微信有统一组件/接口要求）。
- 完成小游戏所需的**备案**与主体资质；知识答题类目注意不要触碰医疗诊断、投资建议等需专项资质的内容表达，题目文案保持科普口径。
- 广告内容由微信广告平台投放，避免在题目里为具体商品/金融产品做诱导性背书。

## 五、发布前检查清单

**代码 / 配置**

- [ ] `project.config.json` 的 `appid` 已替换为真实小游戏 AppID；
- [ ] `src/config/index.js` 中 `CLOUD.USE_CLOUD=true` 且 `ENV_ID` 正确；`ADS.ENABLED` 按是否已开通流量主设置；
- [ ] 题库已扩写并通过 `npm run validate`，已 `npm run export-bank`，`submitScore` 已用最新 `bank.json` 重新部署；
- [ ] `npm test`、`npm run smoke`、`npm run check` 全部通过；
- [ ] 真机走查：休闲答题/反馈/收藏/提示、每日挑战完整一局与失败再战、结果页提交、排行榜、错题复测、我的知识、成就；
- [ ] 弱网/断网走查：榜单与提交的提示正确，休闲玩法不中断；
- [ ] 包体核对：主包 ≤ 4MB（题库走包内、无远程资源，当前远低于上限）。

**平台 / 合规**

- [ ] 小游戏名称、图标、简介、截图；
- [ ] 备案、主体资质、用户隐私保护指引/隐私协议；
- [ ] 云开发环境为生产环境（不要用即将到期的临时环境），集合权限为仅云函数可读写；
- [ ] 达 UV>500 后开通流量主并填入激励视频广告位 ID；
- [ ] 提审备注里说明玩法与广告触发方式，避免审核误判为诱导。

## 六、上线后建议监控

- 云开发控制台：函数调用次数、运行时长、数据库读写、资源点消耗（接近免费额度即预警）；
- 客户端已预留本地埋点队列（`src/services/analytics.js`），事件覆盖启动、进页、作答、挑战完成、广告请求/发奖、网络切换、提交结果；二期可加一个 `track` 云函数或微信数据分析做漏斗（日活 → 挑战参与 → 完赛 → 看广告 → 次日留存）。
